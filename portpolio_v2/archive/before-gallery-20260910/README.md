## 화면과 내용

히어로: **흩어진 요구와 일을 정리해, / 팀이 오픈할 수 있게.**

기존 흩어진 요구 → 기준 정렬 연출을 유지한다. 정책 설계뿐 아니라 고객 협의와 내부 조율까지 문구에 포함했다. AI는 보조 설명과 개인 프로젝트에서 다룬다.

| 순서 | 사례 | 드러낼 판단 | 상세 |
|---|---|---|---|
| 01 | 아르피나 | 기존·신규 회원 요구를 접수 정책으로 구체화, 오픈과 검수 | case-arpina.html |
| 02 | 동아대 | 기존 Google Sheets 관리표 개편, 진척 가시성·검수·우선순위 | case-donga.html |
| 03 | 상지건축 | 고객과 합의를 쌓고 내부 작업 시간 확보, 50주년 자료 분석 | case-sangji.html |
| 04 | 통합 CMS | 공통 기능과 고객별 요구 분리 | case-cms.html |
| 05 | 핸디 협업 | 점수화의 부담을 확인하고 중단, 이유 설명과 실무 지원 | case-ops.html |
| 06 | 이음 + WebOps Builder | 사용자 앱과 운영 콘솔을 직접 구현·검증 | case-eum-webops.html |

대표 3건은 같은 제목·본문·결과·실제 화면 그리드로 구성한다. 이어지는 3건은 행 전체가 상세 링크다. About의 경력과 8/6/8건 프로젝트 목록을 보존했고, Contact에는 이메일·QR과 QR에서 확인한 오픈채팅 직접 링크를 제공한다.

하단과 상세는 같은 종이색 배경, 얇은 구분선, 잉크 블루 강조를 사용한다. 상세는 설명 바로 다음에 해당 화면·도식을 배치한다. 별도의 대화문 장면과 반복되는 어두운 전환 장면은 제거했다.

## 동작과 접근성

- 큰 고정 구간은 히어로 하나(280svh). 첫 사례는 그 안에서 올라오며 정렬선을 이어받는다. 이후는 자연 스크롤이다.
- 대표 사례 버튼과 Work는 `#feature`에 도착한다. 첫 사례가 숨겨져 있을 때는 내부 링크를 비활성화하고, 이동 완료 후 접근할 수 있다.
- 모바일(860px 이하), 높이 680px 미만, 동작 줄이기 설정, 첫 사례 내용이 화면 높이를 초과하는 환경에서는 고정 연출 없이 자연스럽게 읽힌다.
- 스크립트가 없어도 본문과 프로젝트 펼침을 읽을 수 있는 기본 CSS를 둔다.
- 사례 등장·밑줄은 한 번. 사진 조명은 포인터에만 반응한다. 영수증은 열 때 인쇄 후 한 번 움직이며 계속 흔들리지 않는다.
- 관리표만 자체 가로 스크롤을 허용하며, 넘칠 때 키보드로 접근할 수 있다.

## 사실 표현의 경계

- 동아대는 Excel 또는 Google Sheets 신규 도입 사례가 아니다. 기존 Google Sheets 체계를 개편한 사례다. 표의 사이트명·담당·수치는 설명용 재구성이며 실제 운영 데이터가 아니다.
- 핸디는 스토리 포인트를 정착시킨 성공 사례가 아니다. 반복 논의와 적용 시도 후 구성원 부담을 고려해 중단한 판단이다.
- 상지 리뉴얼 약 5개월 계획 → 약 1년 진행은 사용자 진술이다. 기존 참여 기간과 전체 계약 기간의 정확한 관계는 추가 확인 전이므로 종료 월을 추정하지 않고 리뉴얼 2023 / 50주년 기획 2024로 표기한다.
- 상지 50주년 합동 발표의 경험을 전체 프로젝트 무수정 승인으로 확대하지 않는다.
- 정성 결과에 임의 개선율을 붙이지 않는다. 이음의 출시 전 상태는 유지한다.
- 현재 공개 화면 캡처만으로 과거 정책의 모든 세부가 검증된다고 주장하지 않는다.

검증 범위와 제한은 `PHASE2-REVIEW.md`에 기록한다. 배포는 수행하지 않았다.
