# 프로세스 읽기 구간 수정 — 2026-09-10

사용자가 다음 섹션이 프로세스 하단을 너무 빨리 가리는 문제를 지적했다.

원인: 장면 280svh, 갤러리 margin-top -100svh이므로 스크롤 117svh에서 갤러리 상단이 화면 63svh에 도착했다. 프로세스는 화면 64%에 정렬되며, 마지막 번호는 스크롤 약 135svh에 완전히 나타났다. 따라서 모든 번호가 완성되기 전에 실제 갤러리가 가렸다. 진행률 0.72부터 제목도 사라졌다.

수정: .scene에 정렬 비율 1.8과 읽기 비율 .8을 분리해 전체 360svh로 확장했다. 정렬의 진행 거리 180svh는 유지한다. 제목과 단계의 퇴장은 실제 갤러리 상단 위치를 따른다. 실제 갤러리 자체에 상단 선이 있으므로 이전 별도 연결선을 숨겨 중복을 없앴다. 종이 이미지 셰이더, 하단 효과, 사례와 경력 내용은 유지했다.

1280×900에서 scrollY 1395와 1620 두 위치 모두 프로세스 제목/단계/번호 opacity 1을 확인했다. 갤러리 상단은 각각 945px, 720px이고 번호 하단은 약 606px로 가려지지 않았다. Work 바로가기는 갤러리 상단 0에 정상 도착하고 내비게이션도 밤 배경으로 전환됐다. 관찰한 브라우저 경고·오류 없음. 모바일은 기존 정적 히어로 분기를 유지한다.
